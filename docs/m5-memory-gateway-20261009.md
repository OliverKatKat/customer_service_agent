# M5 记忆网关边界与上下文整理（2026-10-09）

## 本轮目标与基线

原网关在 Planner 前整理消息，但使用固定的 128,000 token 阈值，且缺少可靠的当前轮保留、租户身份核对和多工具调用完整性检查。为避免依赖模型输出，先用 `eval_agent/run_gateway.py` 构造短对话、长对话、跨身份、工具调用及超预算场景。原实现的基线报告 `eval_agent/results/gateway_20261009_150821_930115Z.json` 为 **2/6**：身份不一致仍可能进入 Planner；裁剪可能留下半个对话轮次；不完整的工具调用未作为一组移除；当前用户消息过长时可能被裁掉。

改动前的 `memory.py`、`memory_gateway.py`、`graph.py`、`state.py`、`config.py` 保存在 `docs/source-backups/20261009-memory-gateway/`。项目没有 Git 工作树，因此该目录用于逐文件对照和回退。

## 改动与取舍

| 层次 | 现在的行为 | 原因与取舍 |
| --- | --- | --- |
| 作用域 | 网关核对 state 与 zhi'qiRunnableConfig 中的 `tenant_id`、`customer_id`、`ticket_id`；缺失或不一致时设置 `gateway_blocked`，LangGraph 条件边直接结束。 | 在 Planner 读记忆、调用工具之前阻断身份串线。它核对的是上游提供的可信上下文，数据库归属仍由工具和 API 层验证。 |
| 上下文预算 | `MEMORY_CONTEXT_MAX_TOKENS` 可由环境变量设置，默认 32,768；使用缓存的 tiktoken 编码器，对消息内容及工具调用做近似计数。 | 替换固定 128,000 阈值，给 Planner 系统提示词和模型回复留余量。计数并非 DeepSeek 精确 tokenizer，默认值也不是模型上下文规格声明。 |
| 裁剪 | 保留系统消息，按完整的客户轮次从新到旧选取；当前客户轮次超预算则阻断 Planner。 | 避免只留下回复、删掉用户问题，或让模型在丢失本轮输入后继续执行。 |
| 工具记录 | 成组核对一次 AI 工具调用的全部 call ID 与 ToolMessage；缺失、重复、孤立时移除该组并提示重新核验。 | 避免残留不完整的工具结果误导下轮规划。 |
| 旧消息中的偏好 | 仅从将裁剪的显式客户偏好中做本地规则提取，并带租户、客户、来源工单 ID 入队现有记忆任务。入队失败时阻断本轮裁剪。 | 复用已有带作用域的偏好存储；避免队列明确失败后仍删除原文。入队成功不等于后台写入成功，因此还不能称为可靠归档。 |
| 删除操作 | 待删消息必须有 ID，使用 `RemoveMessage` 提交；缺少 ID 时阻断。 | 防止裁剪结果与检查点记录不一致。 |

此次选择了**完整轮次裁剪 + 少量显式偏好存储**，没有引入自动生成的长对话摘要。摘要若写回上下文，需要先定义来源引用、用户更正、敏感信息保留期限和后台写入确认，否则可能把错误摘要变成后续工单的依据。

## 评估结果

模型无关的最终报告 `eval_agent/results/gateway_20261009_151643_856813Z.json` 为 **7/7**，覆盖短上下文、身份不一致、完整轮次裁剪、偏好作用域入队、入队失败不删历史、不完整多工具调用、当前轮超预算。该脚本将 Celery 任务换成记录器或失败注入，不写数据库，也不调用 LLM。中间的 6/6 报告为 `gateway_20261009_151124_848705Z.json`。

使用隔离的 `agent_eval_v3` Postgres、Redis、Qdrant 与重新启动的 API、Worker 复跑后，客户记忆 **13/13**（`eval_agent/results/memory_e2e_20261009_151358_833922Z.json`），租户公司知识 RAG **12/12**（`knowledge_e2e_20261009_151437_597797Z.json`），原有一条付款后退款路径 **1/1**（`agent_20261009_151508_636855Z.json`）。这些是短流程回归，证明改动没有破坏已覆盖路径，**不能**证明真实 32k token 长会话的裁剪和恢复可靠性。另已检查 graph 中 `gateway_blocked=True` 路由至 END，正常情况进入 Planner。

## 尚未完成

1. 用真实 API/Worker 跑多轮、接近预算的长会话，保存 trace 和检查点，量化实际 tokenizer 偏差、延迟、费用与裁剪后答复质量。当前只有合成消息的直接节点评估。
2. 为偏好存储建立可核验的后台完成状态与失败补偿；再考虑把旧轮次摘要持久化，并在摘要中保留来源工单及时间。现在只有成功入队的同步确认。
3. 补偏好更改、冲突、撤回和保留期限的产品规则与数据集；现有提取只覆盖少数显式偏好。
4. 给知识 RAG 扩充干扰文档与主题，单独评估召回、引用、拒答、延迟及成本；默认商户手册路径尚需独立回归。

因此，当前实现可称为**作用域核对与安全裁剪网关**；尚不能称为完整的长期记忆管理系统。
