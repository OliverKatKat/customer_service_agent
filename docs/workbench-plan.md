# 售后工作台轻量演示计划

目标是做一个能用于求职展示、自己能解释和修改的项目。当前没有真实商家数据，采用明确标注的合成数据即可。此前八周企业方案保留作参考，不再作为当前执行要求。

## 数据怎么来

沿用现有测试中的虚构商家、客户和订单，整理成可重复执行的演示数据脚本。先设定一个耳机店，准备约20至30笔订单、10至15条售后申请和一份简短商家政策；另加少量第二商家记录验证权限隔离。

数据固定编号和时间，围绕业务故事编写，不追求真实行业分布或数量规模。页面读取数据库中的演示记录，不把数字直接写死在界面里。README 写明数据为合成样本，项目成果以实际功能和验证结果描述。

每完成一步就实际演示一次，暴露的问题就地修复。暂不固定八周排期，也不等所有功能齐全才准备投递。

## 三条演示故事

1. 客户反馈耳机故障，系统找到订单和适用政策，提交人工审核，管理员批准后显示模拟执行结果。
2. 客户提出不符合演示商家政策的请求，系统引用依据说明情况，必要时转人工，不编造处理承诺。
3. 客户继续联系同一售后申请，界面显式携带 case_id，工作人员能看到前后记录，避免误建成互不相关的申请。

现有案件、备注、待办、权限和24项测试作为基础继续使用。台账计数与原因分布已具备基础，不先建设完整经营分析。

## 暂缓的工作

大规模数据生成、完整经营事实投影、自然语言查数、多系统接入和生产性能目标暂缓。金额精度等深度改造不作为这次演示版的前置条件；当前只保留模拟执行，不接真实支付或制作真实财务报表。

如果后续面试或实际使用暴露出明确需求，再针对性补功能。当前优先顺序为：演示数据、处理闭环、AI 审核材料、展示与表达。
