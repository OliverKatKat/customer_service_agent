# 项目未来规划（Roadmap）

> 目标：把「售后客服 Agent」从"能跑通的 demo"逐步完善为多模块、可评估、可观测的系统。
> 原则：每项优化都要能落到**数字**或**可展示物**上，不做纯堆代码的优化。

## 总览：两个阶段

| 阶段 | 内容 | 状态 |
|---|---|---|
| **Phase 1** | 客服 Agent 打磨（评测 + 展示） | 进行中 |
| **Phase 2** | 售后经营分析台（M0–M7） | 规划中 |

---

## Phase 1：客服 Agent 打磨

### 已完成

- ✅ 演示页面：`/chat`（客户对话 + SSE 流式步骤）、`/review`（人工审核工作台）、`/demo`（入口页）
- ✅ 演示截图 + README（mermaid 架构图 + 流程截图）
- ✅ LLM-as-a-Judge 语义复核（`eval_agent/judge.py` 六维判据 + 人工校准）

### 待办

**高优先级**

1. **RAGAS 套知识检索**：faithfulness / answer_relevancy / context_relevancy，补齐 RAG 侧指标。
2. **适配 τ²-bench**：拿客服 Agent 的业界公认分（pass^k）。
3. **评测集扩充**：多租户 / 权限 / 金额边界 / 状态机 / 多轮追问。

**中优先级**

4. **多轮对话 + 跨工单记忆演示**：坐实"记忆"能力。
5. **可观测 dashboard**：Prometheus / Grafana + tracing 截图。

**长期**

6. pytest + CI、幂等键 + 死信队列、更多工具（只读查询 / 部分退款 / 换货）。

---

## Phase 2：售后经营分析台（M0–M7）

在客服 Agent 之上规划的经营分析能力（经营总览 / 贡献下钻 / 受限 NL2SQL），数据层 M0–M1 已完成：

- **M0**：指标契约（5 指标 + 七类数据对象 + 指标×维度矩阵）、双租户金样本（32/32 通过）
- **M1**：分析 schema（6 张事实表 + 视图）、固定种子合成数据生成器（确定性复跑）

待实施：

| 里程碑 | 内容 |
|---|---|
| **M2** | 只读查询通道 + 总览/贡献 API + analyst 角色 + 明细/权限回归 |
| **M3** | 经营总览页 + 贡献下钻 + 证据抽屉 |
| **M4** | 受限 NL2SQL：语义目录 + QueryPlan + NL 入口 |
| **M5** | 冻结评估题集（40–60 题）+ 部署/演示 |
| **M6/M7** | 异常候选 / 调查记录 / CSV 导入 / 查询优化 |

---

## 借鉴的工程实践

- **评估驱动迭代**：每个优化都用数字记录（违规率 / 命中率 / 一致率）
- **知识库治理**：手册版本化 + 检索来源追踪 + 证据编号闭环
- **多内存平面分离**：客户偏好记忆 vs 知识库，职责清晰
- **可观测**：Prometheus 指标 + 审计日志
