# M5 客户记忆与公司知识 RAG 首轮证据（2026-10-09）

本页是 M4 退款 60 次评估之后的**独立样本**。M4 仪表盘中的公司知识 RAG、客户记忆检索均为 0 次，含义仅是当时那批退款案例没有调用它们；不能与此处结果合并成同一个通过率。

## 客户记忆

`eval_agent/run_memory.py` 在隔离的 `agent_eval_v3` 中完成三轮，每轮使用两名新的合成客户和三张新工单。第一张 Alice 工单明确表达邮件联系偏好；后台把规则提取的偏好写入 Qdrant，并记录商户、客户、来源工单。第二张 Alice 工单的 LangGraph 检查点出现 `search_user_memory`，返回来源工单和邮件偏好，最终答复正确引用。Bob 工单同样调用工具，结果为 `no_match`；伪造跨客户、跨租户上下文的工具调用均为 `no_memory_scope`。

首轮报告 `eval_agent/results/memory_e2e_20261009_115302_003194Z.json` 的 10/10 自动检查漏掉两处回复错误：否认能够记录偏好，以及承诺主动邮件跟进。第二轮 `memory_e2e_20261009_115600_799985Z.json` 的 12/12 仍漏掉“偏好必须由人工客服登记”的错误。第三轮 `memory_e2e_20261009_115748_330937Z.json` 原始自动评分为 12/13；其唯一失败是宽泛正则把“没查到此前登记记录”误判为“系统不能登记”。已收紧评分规则，并核对三轮原始回复；第三轮按修正规则为 13/13，原报告未被改写。详情见 `docs/memory-e2e-eval-20261009.md`。

为处理回复问题，Planner 现在区分“本轮异步尝试保存、尚未确认结果”和“历史检索无结果”；禁止声称没有记忆登记能力或承诺邮件/电话回访。此次没有扩大 `memory_gateway.py` 的作用。客户记忆仍只支持少数本地规则提取的显式偏好，不支持任意历史文本语义检索、偏好冲突更新或撤回。

## 公司知识 RAG

新增 `company_knowledge/tenants/<tenant_id>/handbook.txt` 与专属 Qdrant 集合的租户映射。默认商户仍使用原手册和原集合；其他商户只有存在对应手册与集合时才可用。BM25 只加载该商户手册，向量检索只访问该商户集合，返回文档还会再次核对 `tenant_id`。工具入口在查询前核验活跃商户、客户与工单的数据库绑定。原始检索模块已备份在 `docs/source-backups/20261009-tenant-rag/`。

只把 `merchant_eval_agent` 的三段**合成**知识送入现有 Embedding 服务，索引为 `company_knowledge_eval_v3__merchant_eval_agent`。首轮报告 `eval_agent/results/knowledge_e2e_20261009_120610_316106Z.json` 为 9/10：X2 回复提到了 X1 的“7 秒”，但明确禁止套用，自动规则把这段引用误判为 X2 操作。人工复核后收紧评分规则，同时发现首轮最终回复没有保留知识子 Agent 的出处编号。Planner 已要求转述知识时保留本轮有效 `[K1]` 等引用。

复跑报告 `eval_agent/results/knowledge_e2e_20261009_120829_547627Z.json` 为 **12/12**：X1 工单的最终回复使用手册中的圆形配对键 7 秒步骤并保留有效引用；X2 工单明确说资料不足，引用 X1 仅为解释为什么不能套用；跨客户与跨租户直接工具读取均返回 `no_knowledge_scope`。本次仅有两张端到端工单和三段小型合成语料，不能推出复杂知识库上的检索召回率或线上稳定性。
